# 帧契约（**交付物的语义，不是细节**）

交付位姿的坐标系约定：`position` 指哪里、光轴朝哪、ROBOGUIDE 侧 `UTOOL` 怎么教、`UFRAME` 两条路怎么选。

- 视点的 `position` 是扫描头的**测量参考点**（覆盖率计算里那个"距目标点一个工作距离"
  的点），单位 mm，坐标在**数模坐标系**里；
- 局部 **+Z 就是光轴**，从扫描头**指向零件**；
- `.LS` 里的点位是**笛卡尔位姿**，为了对齐这个契约，ROBOGUIDE 侧的 **UTOOL 必须按这个
  参考点教**。教错 → 所有点位的实际测量距离整体偏掉一个常数，仿真里看不出来，实机上
  是系统性误差。

坐标系口径有两条路：把 `UFRAME 1` 教到数模原点（底座固定，只需教一次），或用
`--place "x,y,z,w,p,r"` 把数模摆进 ROBOGUIDE 世界（此时程序用 `UFRAME 0`）。
**无论哪条，都必须先在 ROBOGUIDE 里确认点位落在零件上**，再谈可达性。

## 第七轴：`E1` 是什么

手臂坐在沿**自己基座系 `+X`** 的直线导轨上时，第七轴会写进每个 `P[n]`，但**两种块的写法不同**：

```
P[1]{                       P[2]{
   GP1:                        GP1:
	UF : 1, UT : 1,             	UF : 1, UT : 1,     CONFIG : 'N U T, 0, 0, 0',
	J1= ..., ..., J6= ...       	X = ..., Y = ..., Z = ...,
	J7=   350.000 mm            	W = ..., P = ..., R = ...,
};                          	E1=   350.000  mm
                            };
```

- **关节块按组内轴号计数**，所以第七轴叫 `J7`（线性轴，单位 mm）；
- **笛卡尔块**叫 `E1`，单独一行跟在 `R = ...` 后面（`R` 行末尾带逗号，`E1` 与数之间补到宽 10，
  `mm` 前两个空格）——这个字节形状是直接按现场单元自己导出的 `.LS` 对过的；
- 零点是导轨自己的零位（`track_limits_mm` / `track_margin_mm` 都按这个读数定义）；
- 笛卡尔点的 `X/Y/Z` **已经含小车位移**，`UTOOL`/`UFRAME` 的教法与没有导轨时一致，不要再把 `E1` 加一遍；
- 两者都要求导入目标是**同一运动组里的七轴**；只配了六轴会在第一个 `J7`/`E1` 行报 `ASBN-009`；
- 没有导轨的导出**一行都不写**，旧程序逐字节不变。`robot.track_emit_e1: false` 可以只关列、不重规；
- 如果某个控制器在关节块里也认 `E1`，把 `robot.track_joint_label` 改成 `"E1"`。

### 导入时报 `ASBN-009 Mismatch number of joint`

就是第七轴那一行引起的：**轴值个数**和控制组里的轴数不一致。两种典型情形：

1. 机器人只配了**六轴** → 三种出路：把机器人配成七轴（同组扩展轴）后原样导入；
   `scanplan ls ... --no-e1` 先看可达性（不重规）；或 `robot.track_enabled: false` 重新规划。
2. 机器人是七轴，但报警落在**关节块**里 → 实测这台控制器**两种拼法都拒**（`J7=` 与 `E1=`，
   列号相同）。所以导轨运行时关节点位默认改写笛卡尔块（带 `E1`）——即与现场导出文件同一种形状；
   代价是那些姿态由控制器再解一次，CONFIG 又退回成提示。要试关节块写法用
   `robot.track_joint_blocks: true`。

导出侧的 `_frame.json` 会把这件事写进 `program.extended_axis`：`written`、`used_span_mm`、
以及没写时那条 warning（"这份计划用了导轨，但程序没命令它"）。


### 导入时报 `ASBN-009 Mismatch number of joint`

就是上面那行 `E1` 引起的：点块里有**七个**轴值，而导入目标机器人只配了**六个**控制轴。
ROBOGUIDE 停在第一个 `E1` 行（列 10），同时抛出 `ASBN-002 Error occurred during load` 和
`ASBN-008 file '<名字>'`——后两条只是"加载失败"与"哪个文件"，真正的因是 `ASBN-009`。

三条出路，按现场值得选：

1. **机器人有导轨**（同一运动组的扩展轴）：在 ROBOGUIDE 的机器人属性里把控制轴加一根
   （或者用现场已导出的程序校对格式），然后原样导入。
2. **机器人没导轨、但要先看可达性**：`scanplan ls ... --no-e1` 重新导出（不用重跑规划）。
   注意这**不会**把姿态拉回六轴可达区——点上仍然是小车在 600 mm 处才够得到的姿态，要看它们就得
   把机器人底座摆到那个 X 上，或者往下第 3 条。
3. **本来就是六轴工位**：把配置里的 `robot.track_enabled` 改回 `false` 再重新规划。只有这一条
   能让"姿态"和"程序"描述同一台机器。

导出侧的 `_frame.json` 会把这件事写进 `program.extended_axis`：`written`、`used_span_mm`、
以及没写时那条 warning（"这份计划用了导轨，但程序没命令它"）。

# 换一批标定数据：从位姿到配置

手上又采了几组 `(关节角, 笛卡尔位姿)` 之后，这份文档说明怎么判断这组数据到底说明了什么、结论怎么落到配置里、以及哪几件事这组数据**根本给不出**。脚本是 [`scripts/fit_robot_pose_bank.py`](../scripts/fit_robot_pose_bank.py)，结论口径与判定线都在 [kinematics.py](../src/scanplan/kinematics.py) 里。

## 仓库里为什么没有标定数据

标定数据是客户工位坐标，按 [CONTRIBUTING.md](../CONTRIBUTING.md) 绝不入库；`scripts/check_repo_hygiene.py` 会拦。因此**「换标定数据」永远是两步：重跑拟合并改数值**，不存在替换某个数据文件这种做法。配置里存的是拟合结果。

脚本只读一个外部 JSON，位置随你放（不要放进仓库）：

```json
{
  "poses": [
    {"joints": [J1, J2, J3, J4, J5, J6],
     "xyzwpr": [X, Y, Z, W, P, R],
     "config": "N U T, 0, 0, 0"}
  ]
}
```

采集时的四条硬要求，缺一条这批数据就只能做参考：

- **同一个 UTOOL、同一个 UFRAME**，整批一致。混了两个 UTOOL 的批次，拟合出来的是一个不存在的工具。
- **关节角与笛卡尔位姿取自同一时刻**。分两次读出来的两行，配出来的是"两个位姿之间"的假几何。
- **姿态要铺开**：J5 正负两侧、J4 大幅转动、J2 前后两个方向、J6 跨圈、至少一组贴近某个限位。位姿都挤在一小片时，臂长的方向和工具的方向会互相补偿，残差仍然很小而参数已经错了。
- **至少一组 J5 > 0**。这条最容易漏：J5 全为负时，`T/F` 字母只能证明"负 J5 配 T"，反过来的那一半永远验证不了（[2026-10-23 那批](#本次结果2026-10-23) 就是全部为负）。

## 四步拟合

### 第 1 步：先判「臂错了」还是「只换了工具」

这一步在拟合之前做，代价一次乘法，但它决定了后面能不能只改两个数。用当前配置跑一遍正向解，把残差搬进**法兰坐标系**看：

```
a_i    = F_i^T · (p_pred_i − p_meas_i)        偏移
Rrel_i = F_i^T · R_meas_i                     姿态差
```

判读只有两行：

| 现象 | 结论 | 处置 |
|---|---|---|
| `a_i` 恒定（组间散布 ≪ 1 mm）且 `Rrel_i` 恒定（散布 ≪ 0.01°） | 臂几何与关节约定都对，**只有工具变了** | 只改 `tool_xyz_mm` / `tool_ypr_deg` |
| `a_i` 随位姿漂移 | 臂几何或关节约定的问题 | **不要去改工具**——工具会把臂的误差吸进去，残差变小而物理模型是错的 |

之所以成立：臂参数一错，腕心就按每个位姿的关节角漂移，残差在法兰系里必然变化；而工具是刚体，它的偏差在任何位姿下都是同一个常向量 + 同一个常旋转。

### 第 2 步：臂与关节约定怎么摆

关节零位、符号、腕部倾角**一律钉住**，只放开五个臂长和工具的六个数。两个理由：

- **`j6_zero_deg` 与工具偏航完全简并**。`flange @ Rz(δ)` 恰好被 `Rt @ Rz(−δ)` 抵掉，一起放开时完全拟会把它拉到 181.209°，解不唯一，而且 `config_string` 的 J6 圈数会跟着算错。
- 腕部倾角必须是**相等的 ±90**，否则 [`_wrist_solutions`](../src/scanplan/kinematics.py:338) 直接 `raise`。这是有意的：这个仓库不实现数值腕解，就是为了不产出"看起来合理"的关节值。

### 第 3 步：工具的解是唯一的

```
p = W + F · Rt · v        R = F · Rt
```

姿态给出 `Rt`（唯一），位置再给出 `v`（唯一）。所以不存在"工具调一调凑残差"的空间；如果第 1 步说臂不对，这里拟合出来的工具也是错的。取整时：臂长取图纸值（312 / 1075 / 1730 / 225），工具取 3 位小数，够用——见第 4 步的容差。

### 第 4 步：三道验收，缺一不可

| 检查 | 判定线 | 它抓什么 |
|---|---|---|
| 逐组残差 | ≤ 0.02 mm / 0.002° | 输入数据本身只到 0.001 mm / 0.001°，这是地板，不是目标 |
| 留一交叉（每次留一组不参与拟合） | 与逐组残差同量级 | 过拟合：`v` 把某一组的噪声吃进去了 |
| 用实测笛卡尔位姿做逆解，还原实测关节角 | gap < 0.01° | **分支错**——残差小但腕解翻过去的场合 |

第三道是这套流程里最容易被跳过、也最容易放过错误的一道。

## 跑一次

```bash
uv run python scripts/fit_robot_pose_bank.py path/to/bank.json
```

输出五段：`stage 1` 的判定、`stage 2` 的参数（含示教器 `UTOOL` 应该显示的值）、`stage 3` 逐组残差、`stage 4` 留一交叉、`stage 5` 的 CONFIG 比对。末尾一行 `PASS` / `FAIL`，并作为退出码。`--skip-loo` / `--skip-branches` 可以在快速迭代时省掉后两段。

脚本开头还会把 `configs/` 与 `RobotParams.disabled()` 对一遍，两处漂移时打 `WARNING`——那意味着**规划器与测试在验证两台不同的机器**。

## 改配置：两处，必须同步

| 位置 | 角色 |
|---|---|
| [`configs/scanner_trackscan49.json`](../configs/scanner_trackscan49.json) 的 `robot` 段 | **真正生效的那份**。`load_config()` 永远先读它当基底，`configs/robot_gate.json` 只写 `"enabled": true` |
| [`src/scanplan/config.py`](../src/scanplan/config.py) 的 `RobotParams.disabled()` | 配置没有 `robot` 段时的兜底值，**同时是测试用的那份** |

只改一处的结果是：要么测试还在验证旧几何，要么命令行跑的还是旧机器。`_validate_robot` 会拦下这几种明显错误：

- `forearm_mm ≤ forearm_offset_mm`（腕心在偏置方向后端，不在前臂轴线上）
- `soft_limits_deg` 超出 `mechanical_limits_deg`
- `j5_min_abs_deg` 不小于 J5 可用带宽的一半
- 任一 `j*_sign` 不是 ±1

## CONFIG 字母怎么推

方法不靠猜，靠数：用**实测笛卡尔位姿**做逆解，挑出与实测关节角最接近的那个根（正常情况差 < 0.01°），再把它的 `(肩, 肘, sign(J5))` 与示教器上那一行逐组比对。

2026-10-23 这一批（8 组）数出来的结论：

| 位置 | 结论 | 证据强度 |
|---|---|---|
| 第 1 字母 `N`/`F` | 与解析解的**肩**分支一致 | 7/8 一致。唯一不一致的那一组，其自带说明（"J5 为正"）也与它自己的数据矛盾，判为该行标注有误 |
| 第 2 字母 `U`/`D` | 与**肘**分支一致（`U`↔`U`） | 8/8，但全为 `U`，`D` 仍未验证 |
| 第 3 字母 `T`/`F` | **`T` ↔ J5 < 0** | 8/8：J5 从 −9° 到 −124° 全部标 `T`。原实现是 `T` ↔ J5 ≥ 0，8 组全错，已按此改正 |
| 圈数 `0,0,0` | 推不出来 | 实测与 `floor(J6/360)` 不对应。用 `--joint-blocks` 写关节指令绕开这一项 |

`T` / `F` 不是装饰：走笛卡尔点位时，它告诉控制器取哪个腕分支。标错的后果是同一个位姿转 180°——这正是 `--joint-blocks` 存在的理由。

## 这批数据给不出的东西

- **软限位**：只有两组贴着 J5 = −124.321° 采集，反证了 `soft_limits_deg[4] = [-125, 125]` 这个下限是真的（`SRVO-115 (G:1, A:5)` 就发生在那一带），可 J1/J2/J3 的上限一个都没测到。
- **肘部 `D` 分支**与**圈数**：没有样本。
- **工具装偏**：拟合只能说出"UTOOL 1 是这个位姿"，说不出"`+Z` 是不是光轴"。这一条必须去示教器核对，见下。

## 换完必须做的一件事：在示教器上核对 UTOOL

脚本打印的 `X/Y/Z/W/P/R` 应与 ROBOGUIDE 里 `UTOOL 1` 显示的完全一致；不一致说明采集时用的不是 UTOOL 1，整批数据作废。

同时看一行容易忽略的数：**扫描头坐标系的 `+Z` 在法兰系里的方向**。规划器把 `+Z` 当光轴（[frame-contract.md](frame-contract.md)），如果这个方向与实际光学朝向相反，导出的 `W/P/R` 会整体差 180°，而残差表一个字都不会提示——它只描述"教出来的 UTOOL 是什么"，不描述"光轴朝哪"。

## 工具记反了，门会怎么错

这是 2026-10-23 那次重标最值得记下来的一件事。用同一批 8 组实测位姿反过来考**旧**配置：4 组**根本解不出逆解**；另外 4 组解出来的 J5 与实测**符号相反**（实测 −84° / −34° / −124° / −124°，旧模型给 +113° / +111° / +71° / +110°），而旧模型还认为这几组"离限位剩 9.6°–27.6° 余量"。

机理只有一个数：两个工具模型对同一个扫描头位姿要求的**法兰朝向差 176.011°**（腕心位置只差 50.9 mm）。法兰翻过去，J5 就换到另一侧，于是"模型说还有 27° 余量"和"现场报 `SRVO-115`（G:1, A:5）"可以同时成立——门并没有失效，它忠实地在评审一台不存在的机器。

两条推论：

- 换工具之前跑出来的所有可达性结论都不能直接沿用，包括 [validation.md](validation.md) 里那一档关节门实测；重标后必须重跑。
- 门自己看不出这件事。残差表、余量表、J5 直方图都只描述"配置自己自洽"，只有**实测关节角**能证明法兰朝向对——所以第 4 步第三道验收（逆解还原实测关节角）不是可选项。

## 收尾验收

```bash
uv run pytest -q
uv run scanplan plan --station input/station_fixed.json \
                     --config configs/robot_gate.json --out output/robot_calib
```

`coverage_report.json` 的 `kinematics` 段看四个数：

- `points_without_solution` 应为 0；
- `min_margin_deg` 应 ≥ `robot.joint_margin_deg`；
- `j5_histogram_deg` 不该全挤在 `0-20`（挤在那儿说明腕解被翻过去了，而残差照样很小）；
- `limits_source` 应是 `soft (intersected with mechanical)`。

## 本次结果（2026-10-23）

8 组，`UTOOL 1`，`UFRAME 0`。

| 参数 | 新值 | 旧值 | 结论 |
|---|---|---|---|
| `base_offset_mm` | 312.0 | 312.0 | 不变（拟合 311.989） |
| `j2_height_mm` | 0.0 | 0.0 | 不变（拟合 0.0005） |
| `upper_arm_mm` | 1075.0 | 1075.0 | 不变（拟合 1075.0003） |
| `forearm_mm` | 1730.0 | 1730.0 | 不变（拟合 1730.015） |
| `forearm_offset_mm` | 225.0 | 225.0 | 不变（拟合 225.001） |
| `tool_xyz_mm` | (−248.001, −26.674, 584.158) | (337.342, 5.849, −557.613) | **变了**，`\|v\|` 651.741 → 635.182 |
| `tool_ypr_deg` | (179.279, −45.934, 172.758) | (0.0, 49.9, 0.0) | **变了** |

- 常向量散布 **0.0129 mm**、常旋转散布 **0.0009°** → 臂与腕约定全部成立，只有工具换了。五个臂长一个没动，这是对上一轮 6 组标定的独立复现。
- 逐组残差最大 **0.0119 mm / 0.0009°**（把参数取整成配置里那几位之后是 0.0134 mm / 0.0010°，仍在判定线内）；留一交叉最差 **0.0147 mm**；用实测笛卡尔位姿逆解还原实测关节角，最大 **0.0026°**。
- 新的工具坐标系与旧的差 **176.01°**（绕法兰 +Y 轴）。也就是说旧配置里"扫描头 `+Z` = 光轴"这条实际上是把光轴记反了：按新拟合，从腕心走到参考点是 `+584 mm` 的局部 `+Z`，而旧值是 `−558 mm`。旧的那一版能解释旧数据，但它描述的是一个朝后装的头——这也是为什么换数据之后必须重新看 `j5_histogram_deg`。
- 门判读：8 组里 6 组 `feasible`；另外两组 J5 = −124.321°，离软限位只剩 0.679°，按 `joint_margin_deg = 5` 本就应该被拒——它们正是现场报警的那类位姿。

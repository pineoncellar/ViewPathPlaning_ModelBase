# 按模块看三个分支：差在哪，最后用了谁

这份文件回答一个问题：**从工件到 .LS 程序的这条链，拆成模块之后，三个分支各自做了什么，
合并时采用的是谁的。**

不写提交号、不写行号；那些在 [`merge-notes.md`](merge-notes.md) 里。这里只讲"这个模块负责什么、
三支的差别是什么、为什么最后落在这个取值上"。

三个来源并列，下文简称：

- **A** = `feature/modelbase3-update`
- **B** = `feature/joint-audit-and-config`
- **C** = `feature/joint-direct-connector`

---

## 管线全景（模块 1 → 12）

```
工件(CAD/STL) + 工位(夹具/底座/追踪器) + 机器人参数
   │
   1 参数与开关 ────────────── 决定后面所有模块"允许做什么"
   │
   2 工位载入与几何清洗 ─────── 对齐自检、面片绕向、双面分割
   │
   3 目标面采样 ────────────── 哪些点要测、哪些点夹持区可以豁免
   │
   4 候选位姿生成 ──────────── 围绕每个瞄准点摆出"可能的扫描头位姿"
   │
   5 可达性判定 ────────────── 逆解、限位、腕部奇异、逐段行走
   │
   6 覆盖评估 ─────────────── 这个位姿到底能扫到哪些采样点
   │
   7 视点选择 ─────────────── 用最少的视点覆盖目标（贪心集合覆盖）
   │
   8 扫描带生成 ────────────── 把相邻视点连成"一路扫过去"的直线段
   │
   9 路径排序与连接 ────────── 排序 + 两条带之间怎么过去（不撞件、不超限）
   │
  10 关节分配与读数 ────────── 每个点用哪组关节角、程序里写哪个数字
   │
  11 交付与校验 ────────────── 写成 .LS、写之前查一遍能不能飞
   │
  12 报告与产物 ────────────── 覆盖率、失败归因、3D 视图
```

**9 和 10 是"路径生成"真正的核心**，也是三支差别最大的地方。

---

## 逐模块对照

### 1 参数与开关

干什么：决定"门开不开、量程用多少、J6 怎么计价、程序怎么飞"。它不写算法，但决定了所有算法的输入。

| | A | B | C |
|---|---|---|---|
| 关节门默认 | **开** | **开** | **关**（保留可复现的旧结果） |
| 可用量程 | 量程 ×1.0 + 余量 5° | 量程 ×1.0 + 余量 5° | 量程 ×0.9 + 余量 5° |
| 腕部分支 | 字母钉死 T（但解集不过滤） | 字母钉死 T 且当约束过滤 | 只准 T（J5 负） |
| J6 | 常量 0.5，不可配 | 权重 1.5 + 上限 60° | 权重 1.0（等于不管）+ 报告 90° |
| 覆盖率目标 | 95% | 99% | 90% |

**采用**：C 的三项参数取值（0.9 量程 + 5° 余量 + 只准 T）+ B 的 J6 权重 1.5 和上限键。
新增两个开关：`scanner.roll_mode`（滚转策略）、`stroke.connector`（连接器策略）。

为什么：0.9 量程是 C 实测"离限位 3° 就 hold 不住"之后收的，A/B 都是 1.0，属于未收；
J6 权重只影响"有多个解时选哪个"，取 B 的 1.5 没有副作用。

---

### 2 工位载入与几何清洗

干什么：把三套数模放到同一坐标系并自检；判断哪些三角面属于薄板的哪一面。

| | A | B | C |
|---|---|---|---|
| 对齐自检 | 有 | 有 | 有 |
| 面片绕向修复 | 无 | **有**（`winding.py`） | 无 |
| 网页点选补充面 | **有**（`ScanRegion`） | 无 | 无 |
| 退化射线/超大网格保护 | **有** | 无 | 无 |

**采用**：三支共有的对齐自检 + B 的绕向修复。A 的两项**这次没并入**。

为什么绕向修复必须进：不修的话，"upper 面"里可能混进 39% 的背面，夹具豁免会把半张面吃掉，
覆盖率数字从第一步就不可信。A 的两项要改覆盖率分母和 3D 视图的数据格式，属于"阶段 1 整版"，留到下一版。

---

### 3 目标面采样

干什么：在目标面上铺采样点；夹持区附近的点可以被豁免（现场不量那里）。

三支做法**几乎一样**。唯一差别：B 额外把"硬特征"（窄槽、贴夹具的边缘）单列一个覆盖率分母，
并在后面补扫；A 额外支持"网页点选一块面加进来"。

**采用**：三支共有的采样 + 夹具豁免；硬特征与点选面未并入（同上，改分母）。

---

### 4 候选位姿生成

干什么：对每个瞄准点，按"距离 × 倾角 × 滚转"摆出一堆候选位姿，然后截断到预算。

| | A | B | C |
|---|---|---|---|
| 关节门在哪一步 | 截断**之前** | 截断**之前** | 覆盖评估时（**晚**） |
| 滚转 | 0°/90° 全摆 | **按光轴锁定一个**，门拒绝时按固定顺序回退 | 0°/90° 全摆 |
| 截断方式 | 每个瞄准点轮流取 | 每个瞄准点轮流取 | 按 seed 随机抽 |

**采用**：A/B 的"门前置" + 轮流截断 + B 的"锁定滚转 + 回退"，并做成可切换的插槽（`roll_mode`）。

为什么门前置：截断预算是几千个位姿，门放在评估期意味着**先花完预算再筛**——一次交付里 786/4000 个候选是白算的。
为什么锁定滚转：0°/90° 混摆会在两条带之间制造 74–95° 的 J6 转动，对扫描没有任何好处；
但锁定会让少数位姿不可行，所以保留固定顺序的回退（45/315/90/…），而不是一刀切。

---

### 5 可达性判定

干什么：给定一个位姿，判断机器人能不能摆出来、离限位还有多少、沿直线走会不会中途丢分支。

这是三支**共同祖先**就有的部分（逆解 + `KinematicGate`），差别在**严格程度**和**逐段验证**：

| | A | B | C |
|---|---|---|---|
| 逆解 | 解析解 | 解析解 | 解析解 |
| 单点判据 | 限位 + 1.0 + 5° | 限位 + 1.0 + 5° | 限位 + 0.9 量程 + 5° |
| 逐段行走验证 | **无**（只查角点） | 有（`move`，L 采样 + 分支跟随） | **有**（`follow`，10 mm 采样、锁分支） |
| 腕部过零（J5=0） | 完全不检查 | 排序里罚 1000° | **硬拒** |

**采用**：C 的"0.9 量程 + follow 逐段验证 + J5 过零硬拒"。

为什么：`X10290` 那次报警是"两个端点都合法、中间丢分支"，只有逐段行走才发现得了；
J5 过零是腕奇异，A 完全不检查，实测它会为了压 J6 把 J5 从 −106° 甩到 +108°（4 次过零）。

---

### 6 覆盖评估

干什么：对每个候选位姿，算它能扫到哪些采样点（视场、距离、入射角、遮挡、追踪器可见性）。

三支**一样**——都是"射线求交 + 追踪器可见性 + 夹具/底座遮挡"。差别只在"门在哪"（已在模块 4 说过）。

**采用**：三支共有实现 + C 原有的评估期兜底。

---

### 7 视点选择

干什么：从合法候选里挑出最少的视点，把目标面覆盖到目标百分比；覆盖不够时再补一轮候选。

三支**一样**（贪心集合覆盖 + 覆盖率目标 + 补候选轮）。A 多一个"候选池为空时返回空选择而不是崩"的小修复；
B 多一个"硬特征优先"的权重。

**采用**：三支共有的贪心 + C 的补候选轮。A 的空池修复没并入（因为候选门前置后这个分支基本不会走到）。

---

### 8 扫描带生成

干什么：把相邻视点连成一段"一路扫过去"的直线（现场是连续扫，不是停稳再拍）。

三支**一样**。A 的 `strokes.py` 在 diff 里看起来改了 1600 行，但用 `-w`（忽略空白）看是 0 行——**只是换行重写**，
不是算法差异。这是最容易误读的一处。

**采用**：三支共有实现（C 的版本），滚转按光轴锁定。

---

### 9 路径排序与连接（差别最大之一）

干什么：决定先扫哪条带、每条的入口方向，以及**两条带之间怎么过去**——不撞零件、不超限。

| | A | B | C |
|---|---|---|---|
| 带间主手段 | 直连 + 侧向让位 + 安全面 | 直连 + 抬升阶梯 | **一次关节直连**（`J` 过去，不插点） |
| 直连失败后 | 侧向让位/安全面 | **抬升阶梯**（小抬升起步 0.35×，朝机器人拉回） | 退刀 L0/L1/L2、**安全面 L3** |
| 角点是否验证 | 只查角点 | 逐段验证 | 逐段验证 |

**采用**：C 的"一次关节直连"为第一级 + B 的"抬升阶梯"为第二级。安全面（L3）**删掉**。
A 的侧向让位和 B 的"朝机器人拉回"没并入。

为什么删安全面：它的角点是**插进去的点**，而"7 个不可达点全是自插角点"正是重写连接器的原因；
多一级兜底就多一批没人飞过的点。
为什么直连是主手段：关节插值每个轴都是线性的，两端合法就**不可能在中段出界**，所以既不需要退刀点也不需要 CONFIG。

---

### 10 关节分配与读数（差别最大之二）

干什么：每个交付点用哪组关节角；程序里那个数字写成多少（同一个姿态可以写成 +19.9° 或 −340.1°）。

| | A | B | C |
|---|---|---|---|
| 选解 | 分支 DP（另加常量 0.5×J6） | 分支 DP（J6 权重 1.5 + 超限罚 10000） | 分支 DP（价格 = 加权最大轴步） |
| 读数修正 | 单向贪心（从前往后一遍） | 单向贪心 | **整链瓶颈 DP**（全链一起选，先压最大步再压总行程） |
| 圈位（CONFIG 第 4-6 位） | 行程外才计圈 | 行程外才计圈、负值拒写 | `floor((j+180)/360)` |
| 字母与 J5 符号 | 钉死 T，**不过滤分支 → 10/10 不一致** | 钉死 T + 当约束过滤（一致） | 按物理符号派发（一致） |
| 超限 J6 的处理 | 只报 | 只报 + 排序罚分 | 只报（阈值 90°） |

**采用**：C 的**整链瓶颈 DP** + B 的 J6 权重/上限/圈位规则 + 新增一道兜底。

兜底（这次新写的）：整链 DP 之后如果还有超限 J6 步，**对非覆盖点重试滚转**（滚转不改变视场），
还压不下去就记录并交给速度梯次（>60° 一律 10%）。覆盖点不动它的滚转——那会改掉已验收的覆盖率。

为什么必须是整链 DP：A 的分支在同一台工位上跑过一次，交付里有**一段 J6 从 −349.9° 写成 −78.6°**，
等于让手腕空转 271°，而它的报告只写 103.9°（按环形差统计）。单向贪心一旦某点写成绕一圈，后面全被拖着走。
这也是这次合并**核心验收项**的由来：报告里的关节步长必须等于文件里的字面步长。

### 11 交付与校验

干什么：把点写成 `.LS`；写之前查一遍"这程序能不能飞"。

| | A | B | C |
|---|---|---|---|
| 逐点表示 | 默认笛卡尔，关节块要 `--joint-blocks` | 逐指令 L/J，默认仍笛卡尔 | `motion`/`representation` **写进视点文件**，导出照抄 |
| 交付校验 | 无 | 无 | **独立 `validate.py`**，永远跑 |
| 导出前拒写 | **有**（`joint_audit`） | **有** | 无 |
| CONFIG 圈位检查 | 有 | 有（负圈位拒写，修 ASBN-009） | 无 |
| 速度 | 关节移动一律 5% | 关节移动默认值 | 按转角分档 50/20/10% |

**采用**：三者合在一起——导出前**双重审计**：A/B 的"拒写"思路 + C 的"独立重算"，再加 CONFIG 列检查
（负圈位、字母与 J5 符号不符、关节块与 XYZ 对不上）。不通过就**不落盘**；`--allow-unverified` 才能生成
"仅供审阅"的文件，并在合同里标记。

一个边界要写清楚：只有**声称带关节**的文件才因可达性被拒；纯位姿交付的可达性按文档约定由 ROBOGUIDE 判，
在那里拦会把一条已文档化的流程悄悄废掉。

---

### 12 报告与产物

干什么：覆盖率、失败归因、关节证据、3D 视图。

三支骨架相同。差别：B 多硬特征覆盖率，A 多 `joint_audit` 块，C 多"三层覆盖率 + 失败归因 + J6 块"。

**采用**：C 的报告结构 + 新增三项：`schema_version`、`kinematics.envelope`（唯一包络）、
`part_winding`（绕向修了什么）、以及**关节步长改成按指令类型的字面值**。

## 各模块的来源分布

| 模块 | 来源（可多支） |
|---|---|
| 1 参数 | **C** + **B** 的 J6 值 |
| 2 几何 | 共有 + **B** 的绕向 |
| 3 采样 | 共有 |
| 4 候选 | **A/B** 的门前置 + **B** 的锁定滚转 |
| 5 可达判定 | **C** |
| 6 覆盖评估 | 共有 |
| 7 选择 | 共有 |
| 8 扫描带 | 共有 |
| 9 连接器 | **C**的直连 + **B**的抬升 |
| 10 关节与读数 | **C**的 DP + **B** 的 J6/圈位 |
| 11 交付校验 | **三家合一** |
| 12 报告 | **C** + 口径修正 |

一句话：把 12 个模块拆开数来源——A 出现 2 处、B 6 处、C 5 处，另有 3 采样与 8 扫描带三支等价
（取任一支结果相同）。这个分布只说明各支的改动落在哪些模块，不构成主次：多数模块里只差一两行，
11 交付校验就是三家各出一段拼起来的。
A 独有的两项（点选补充面、退化射线保护）这一版没进来。

## 三个"看起来像差异、其实不是"的坑

1. **`strokes.py` 改了 1600 行** —— A 那边只是换行重写，忽略空白后是 0 行。
2. **逆解和关节门不是三支的差异** —— 三支共用一个祖先，差别只在"门的松紧"和"有没有逐段验证"。
3. **覆盖率目标 90/95/99 不是算法** —— 是配置里的验收口径，换个数字点数和覆盖率都会变，
   所以对比之前必须先对齐（这次实验统一设成"选到不再增长"）。

## 为什么是这套取舍

- **三支的现场证据量不同**：实测限位、8 组实测位姿标定、T/F 两次导入试验、连接器实机验证只发生在 C 上，
  A/B 停在离线对比。默认值因此取有现场闭环的那份，其余做成可选开关——这是按证据取舍，不是给三支排名。
- **B 的改动多为局部函数**：绕向修复、滚转回退、J6 价格、圈位规则、导出审计，接进去不动主干。
- **A 的改动多触及数据模型**：补充面和硬特征都要动"覆盖率分母 + 报告 schema + 3D payload"，
  按"先收敛、后扩展"的顺序，放在下一版更安全。

# 本机浏览器工位界面

`scanplan web` 启动的界面走完一次完整流程：导入数模、三点配准、跑规划、下载 `.LS`，以及拿到程序后必须在 ROBOGUIDE 里核对的事。规划过的项目留在本机的历史库里，可以随时重新打开、补下载或删除。

## 用网页界面走完一次：配准 → 规划 → 出 LS

```powershell
uv run scanplan web                     # 默认 http://127.0.0.1:8765，只监听本机
uv run scanplan web --port 9000         # 换端口
uv run scanplan web --host 0.0.0.0      # 允许局域网内其他机器打开
```

浏览器打开提示的地址就是完整流程：导入数模 → 三点配准 → 跑规划 → 下载 `.LS`。全部计算都在
这个进程里做，数模与产物不发送到任何外部服务；每次运行落在 `output/web_runs/<运行名>/`。

### 局域网访问

默认 `--host 127.0.0.1` 只接受本机连接。绑 `0.0.0.0` 后启动日志会列出本机所有可访问地址
（如 `http://192.168.1.20:8765`），跨机访问还需在 Windows 防火墙放行该端口（管理员）：

```powershell
New-NetFirewallRule -DisplayName "ScanPlan Web 8765" -Direction Inbound `
                     -LocalPort 8765 -Protocol TCP -Action Allow
```

该服务**没有登录校验**：任何能连到端口的人都能提交规划任务、读取历史记录并下载输出，所以只应
在可信内网使用；需要跨网访问时请在前面加一层带身份验证的反向代理，不要把端口直接映射到互联网。

### 1. 模型、扫描面与定位（第 01 步）

- **本次运行名称**：留空则按时间自动命名。
- **方案**：把当前整套配置存下来，重启程序后一键恢复。详见下一节。
- **工位模型**：零件模型与夹具模型必填，底座可选（留空时自动使用 `input/base.stl` 作为默认底座；
  该文件也不存在时才生成一块位于零件下方的参考平板作遮挡基准）。可直接上传 STL / OBJ / PLY / OFF / 3MF / GLB，以及 STEP（`.stp`、
  `.step`）、IGES（`.igs`、`.iges`）、BREP——后三种由服务端调用 OpenCASCADE 三角化，需要可选
  依赖（`uv sync --extra cad`，或 `pip install cadquery-ocp`），没装时页面只接受网格格式。
  PRT / SLDPRT / CATPart 等原生格式没有免费读取器，会提示先在 CAD 里导出 STEP 或 IGES。
  导入的模型**当前坐标直接当整车坐标**，所以三份数模要先在 CAD 里按装配关系摆好，单位毫米。
- **整车主扫描面**：`±X` / `±Y` / `±Z` 六选一；也可以按「根据模型自动推荐扫描面」（统计模型
  主平整面面积）或「在模型上点选扫描面」。整车轴固定为 X 前−后+、Y 左−右+、Z 下−上+。
- **扫描范围**（没有开关，是定义）：主扫描面所在的那一面板料，**加上由它冲压出来的翻边与立壁**，
  按拓扑归属而不是按朝向决定；**背面不扫**，冲裁断面与夹持区也不算目标。翻边和立壁正对主面的
  相机扫不到（视场与壁面平行，几个毫米外入射角就超限），所以规划模式里的倾斜种子族专门铺在
  偏离主方向 ≥45° 的墙上，一条带这样斜着扫过去。**侧面本来就难扫，多给视点是允许的**：倾斜
  种子族现在是每 40 mm 一颗、最多 192 颗（旧值 60 mm / 96 颗），想再加密就调
  `stroke.side_scan_spacing_mm` / `side_scan_max_seeds`。
- **现场测量坐标系**：`机器人 UFRAME 1` 或 `机器人基坐标 / UFRAME 0`。它同时决定第二步现场
  坐标以哪个坐标系量、以及导出的 `.LS` 写哪个 `UFRAME`。
- **高级配置**（默认收起）：交付模式、规划速度、规划模式、路线风格、覆盖率目标、扫描带角价
  都收在这一个折叠面板里，平时只占一行。收起时标题右边那行小字就是当前生效的配方
  （例如 `扫掠带 · 快速网格 · 扫掠优先 · 整齐 · 覆盖率 99%`）：它由控件本身推出来，
  所以折叠起来的显示不会和面板里的选择打架。
  面板**打开时的起点值**由服务端 `/api/config` 的 `defaults` 给出（`scanweb.SITE_DEFAULTS`），
  和配置文件里的**出厂值**是两回事：出厂值（`标准` / `直连` / 不设覆盖率上限）是命令行与回归
  基准的参照，面板起点是这台工位实测合用的那套配方。两者故意不合并——改配方只改一处，
  而 `--plan-mode standard` 仍然名副其实。这六项都会随「方案」一起保存和读取（见下一节）。
- **交付模式**：`扫掠模式 · 连续扫描带`（默认，`L` + `CNT0` 一路扫过去）或
  `纯位姿模式（旧版）`（`J` + `FINE`，只给孤立位姿，不承诺点间运动）。
- **规划速度**：`精确` 或 `快速`（面板默认 `快速`）。快速模式只把采样网格放粗一档
  （3 mm → 10 mm，选项里写的是服务端实际会用的两个值），**不关扫描带、不改关节检查步长**。
  它把一次真实零件的等待从十几分钟压到约两分钟，用于反复迭代关节解算；覆盖率数字只描述
  路径形状，**不能当验收依据**。勾选下面的「跳过遮挡测试」会完全不测视线遮挡（更快，但可能
  "隔着零件"覆盖到采样点）。快速运行的结果里会有
  `规划速度：快速 …（数字只描述路径形状，不能当验收依据）` 一行，
  下载的 `planning_report.html` 顶部也有同样的警告条。
- **规划模式**：`标准`（出厂值）或 `扫掠优先`（面板默认）。这一项决定选择阶段**允许用哪些东西**，
  和「路线风格」（怎么连）是两条独立的轴，可以任意组合。`扫掠优先` 一次把三件事一起做：
  ① 倾斜种子族铺满一圈（3 个切向 × 2 = 6 个轴，每 60 mm 一颗，只铺在法向偏离主方向 ≥45° 的墙/翻边上）；
  ② 关节包络不再自己缩一圈（量程用满、余量 0°）；③ 一条扫描带按一个位姿计价。
  单独动任何一件都量不出效果，所以合在一个模式里。**代价：点数与运行时间上升，姿态余量降到 0°，
  也就是贴着控制器限位跑**（仍在软限位内、仍避开 J5 奇异）。两档的覆盖率**不能互相作为回归基准**。
  配置键是 `stroke.plan_mode`，命令行对应 `--plan-mode`，报告里 `route.plan_mode` 与
  `route.plan_mode_settings` 记录实际生效值，摘要的 `strokes` 行写「几条带 + 几个停点」。
- **最大视点点数**：留空 = 不限制（配置 `target.max_points: null`）。填了就变成程序点数的
  **硬上限**：选择阶段每选一个停点或一条扫描带都检查，超了立刻停手，报告的 `budget` 块写明
  `budget_bound`。它和「覆盖率目标」是两条独立的刹车——一个按**面积**算够就停，一个按**停点数**
  算够就停，两个都给时哪个先到就停在哪个。看某一面到底能扫多好时先把它放大；要控制现场程序
  长度时把它压到程序能接受的点数。
- **扫描带角价（转角/条）**：默认 2.0，即一条带真实要的两个转角，单点恒为 1。这是唯一决定
  「扫」和「停」比例的旋钮：一个停点只盖一个视场，一条带要多付一个停点换长度，所以按 2.0 算，
  短于约两个视场的带会输给盖住同样面积的两个单点。调成 1.0 就是「一条带按一个位姿算」，
  凡是能扫的地方都优先扫。它是**偏好不是事实**：不改变可达性，也不改变能不能交付。
  命令行 `--stroke-corner-cost`。
- **路线风格**：`直连`（出厂值）或 `整齐`（面板默认）。差别只在两条扫描带之间的**第一个动作**：
  `直连` 走一次关节移动（点最少，但 TCP 是弧线，程序读起来是绕的）；`整齐` 改成直线直飞，
  通了就不插任何点，直线被挡时绕光轴垂直方向侧移一个等待点，侧移也不成才回落 `直连` 的链路
  ——**不会因为要"整齐"就丢扫描带**。`整齐` 同时给"换臂型（CONFIG 族）"和"腕翻转"计价，
  避免为省几十度行程让整臂甩一圈。两档的点数与覆盖率**不能互相作为回归基准**；运行结果与
  下载的报告里都有 `route` 块记录实际生效值。配置键是 `stroke.route_style`，命令行对应
  `--route-style`。
- **覆盖率目标（%）**：面板默认 99。达到目标后选择阶段立即停手，**并且跳过针对漏扫区的二次瞄准**
  （`refinement` 整轮不跑）——零件上那些成片的斜坡、孔沿缺口就是这样留下的。想再补就把目标抬到
  99~100，或勾「不设上限」（输入框留空等效，也就是配置里的 `coverage_target_pct: null`）：
  这时选择一直跑到没有新增覆盖为止。
  代价是程序点数、关节重定向次数和单步关节变化一起上涨。结果详情里有一行 `覆盖率目标`。
- **关节限位筛选**：**始终开启，没有开关**。规划期就做逆解——每个候选位姿各轴离限位至少 5°、
  `|J5| ≤ 125` 且远离 0（腕奇异），否则不进选择；扫描带在半路越界就停止生长。结果详情里固定有一行
  `关节筛选：始终开启 · 每点带 CONFIG 与关节解`，报告里的 `kinematics` 块给 J5 直方图、分支直方图、
  最坏单轴步长和无解点数。带门的覆盖率必然低于纯几何（这台机器实测 99.0% → 91.8%），
  那是关节门如实反映现状，不是判据写错了；不带门的旧行为命令行还能跑，用不含
  `configs/robot_gate.json` 的配置即可。
- **导出默认逐点写 CONFIG**（CLI 的 `scanplan ls` 要显式加 `--per-point-config`）。字母一律是
  `T`（负 J5 那支），真正起作用的是**圈位**：`N U T, 0, 0, 1` 表示 J6 取 +196.7 而不是 −163.3。
  少了这一位，控制器自己挑读数，J6 会在 ±180 接缝上多转一整圈（2026-11-02 实测 298.6°），
  见 [configuration.md](configuration.md#腕部分支只能选-tj5-为负)。
- **定位点数量**：3 点或 4 点。

### 2. 在 3D 模型上点定位点，再填现场坐标（第 02 步）

1. 在模型上按顺序点击零件表面的同一个物理基准特征，序号要与模型下方表格里的现场坐标一一对应。
2. 右键或「撤销最后一点」回退，「清空选点」重来；`适配视图` / `沿扫描面观察` 用来摆视角，
   3D 面板工具栏里的 `夹具` / `底座` 勾选框控制遮挡模型的显示。
3. 在表格中逐行填入该点的现场坐标（mm，在第一步选的现场测量坐标系里量）。
4. 点数到齐后自动计算配准，显示 `RMS` 与最大残差；超过「配准最大误差限值」（默认 50 mm）
   时拒绝出结果——这时应回去核对点位，而不是放宽限值。

### 保存与读取方案（改算法重启后不必重新标点）

改算法要重启 `scanplan web`，页面状态会清空——以前这意味着重新导入三个模型、重新在 3D 上
点定位点、重新敲一遍现场坐标。现在在「本次运行名称」下面有一组 **方案** 按钮：

- **保存当前配置**：以「本次运行名称」（留空则用 LS 程序名）为方案名，存下**整套现场配置**
  ——三个模型文件、在 3D 模型上点选的定位点、手动填入的现场坐标，以及扫描面/现场坐标系/
  配准误差限值/LS 程序名，还有「高级配置」里的全部六项（交付模式/规划速度/规划模式/路线风格/
  覆盖率目标/扫描带角价）。同名再存会覆盖旧的。
- **读取**：从下拉框里选一个方案，一键把上面这些全部恢复；模型直接从磁盘读回，不需要重新选文件。
- **删除**：连同该方案的模型副本一起删掉。

存放位置是 `output/web_runs/setups/`，一个方案一个文件夹：`setup.json` 记录点位与设置，
`part.stl` / `support.stl` / `base.stl` 是当时用的模型副本。所以数模**必须**随方案一起保存
（浏览器只给字节、给不出路径），也因为如此，别的机器上拿不到你本机选的文件。

两点值得知道：

- 方案只存"输入"，不存规划结果；恢复后仍要按第 03 步点「开始规划」。
- 恢复的是当时那一刻的数值。之后改了 `configs/*.json`，方案里的采样网格、交付模式等**不会**
  跟着变——它记录的是你当时点的那些值。

### 3. 规划并导出（第 03 步）

- **LS 程序名**：会变成 `.LS` 与配套 CSV/JSON 的文件名，必须以字母开头、只含 `A–Z` / `0–9` /
  下划线、最多 16 字符（例如 `PART01`）。
- 点「开始规划扫描路径」，页面依次做配准、目标面分割、视点与扫描带规划，全部在本机完成。
  上传阶段按真实字节进度推进；规划阶段由服务端逐阶段回报（坐标配准 → 目标面分割 → 候选视点
  → 遮挡计算 → 扫描带规划 → 报告生成 → 交付导出），进度条和阶段标签都以回报为准，下方还会
  显示该阶段的计数与已用时间。停止回报超过 8 秒（例如旧版本服务端，或某个阶段确实很久没有
  中间结果）时，进度条改用只基于已用时间的保守估算，且**最多走到 90%**，不会提前停在 99%
  假装快完成；请求结束才跳到 100%。
- 结果区显示目标面覆盖率、扫描视点数、目标采样点、漏扫点数与本次规划耗时，并可「查看扫描
  路径」把程序顺序叠到模型上，或「打开 viewer.html 3D 分析」逐视点、逐采样核对。
- 「查看扫描路径」的画法与 `viewer.html` 同一套读法：**亮色粗线 = 扫描带**（同一条带的两端），
  **灰蓝色细线 = 过渡/退刀**（换条时的移动），且两者都**按深度遮挡**——在零件背面的线就是背
  面，旋转视角才看得到。以前整条路径关掉深度测试画在模型上面，一条完全没碰零件的计划也会
  看着像穿模。
- 下载列表里 **`<程序名>.LS` 就是交给 ROBOGUIDE 的程序**；同批还有 `<程序名>_points.csv`
  （点位表）、`<程序名>_frame.json`（帧契约）、`planning_report.html`、`coverage_report.json`、
  `registration_report.json`、`summary.txt` 与三个 CSV。

规划用的是本次界面导入的零件 STL：生成前会同步覆盖项目 `input/part.stl`，并把同一份副本按
配准变换写进该次运行目录，不会误用其他运行遗留的模型。

### 4. 定位点改动后重新定位路径（在第 03 步里）

完成一次规划后，结果区多出「定位点复核 · 重新定位」：表格列出这次运行用到的 CAD 点与现场
坐标，改动任一列的现场 X/Y/Z 会立即重算配准残差并逐点显示；残差落在限值内时才能点「按新坐标
重新定位路径」。

这一步**不重新规划**，只对已交付的路径做一次刚体变换：路径相对零件是刚体运动，所以
`Δ = T新 · T旧⁻¹`——视点与光轴、扫描带、`.LS`、覆盖报告里的视点记录与漏扫簇中心、漏扫/豁免
点云、3D 页面用的采样点云 `target_samples.npz` 一起跟着走。耗时从几分钟降到一两秒，而且同一份
规划不会因为一次点位修正变成另一条路径。

- 改的是**现场坐标**；CAD 点取自原运行（点错了要回第 02 步重新选点）。
- 误差限值在复核区里能直接改，改完立即按新限值重新校核。
- 沿用原运行的 LS 程序名、运动/速度/终止类型（读自原 `_frame.json`）、交付模式与扫描顺序；
  扫描带的程序顺序原样保留。
- 新运行写进 `<原编号>_reloc`（重名再追加时间戳），原运行及其 `.LS` 保持不动。

变换做不到的三件事写进 `registration_report.json` 的 `relocalisation` 与覆盖报告，而不是
假装重算过：

1. **覆盖率不变**：零件与路径一起移动，可测集和覆盖面积就是原运行的数字；
2. **`tracker_ok` 没有重算**：跟踪器不跟着零件走，视点相对跟踪器的位置已经变了；
3. **机器人可达性 / 关节限位没有重算**：原 `CONFIG`、关节角是旧坐标系下的判断，已从交付的
   `viewpoints.json` 里**丢弃**而不是沿用。

修正量相对工作距离较大、跟踪器本来就勉强，或开着 `robot.enabled` 时，应改完点位后完整
重新规划一次。

### 5. 历史项目：复用与清理

每次规划成功后，页面把这次运行写进本机的 SQLite 库 `output/web_runs/history.sqlite3`
（WAL 模式）：运行名称、程序名、时间、状态、覆盖率、视点数与完整交付清单。数据库和运行目录
一样只在本机，不随仓库提交。

- 左侧「历史项目」页可按名称 / 程序名 / 运行编号检索；点开一条记录会把那次结果整块载回来，
  指标、下载列表与 3D 视图都指向那次的原始产物，同时把零件、夹具、底座与定位点/现场坐标
  重新导入工作区。
- 「新建项目」会先清空当前工作区（选点、现场坐标、上传的模型、结果区），避免在旧结果上接着改。
- 删除记录会同时删掉 `output/web_runs/<运行名>/` 目录，`.LS` 与报告一并消失。
- **和「方案」的分工**：历史项目恢复的是**一次已完成运行的输入 + 结果**，前提是那次已经跑过；
  只想保存输入、还没规划就要重启，或者想留几套互相独立的现场配置，用第 01 步的「方案」。

### 6. 拿到 `.LS` 之后，在 ROBOGUIDE 里必须做的三件事

1. 核对 `UFRAME`：与第二步选的现场测量坐标系一致（`UFRAME 1` 或 `UFRAME 0`）。
2. 核对 `UTOOL`：按**扫描头测量参考点**教，工具 `+Z` 沿光轴（见[帧契约](frame-contract.md)）。
3. 判可达性与碰撞；报不可达时先换 `CONFIG` 构型再试。

网页端只做几何规划，不替代机器人仿真与现场安全确认。
